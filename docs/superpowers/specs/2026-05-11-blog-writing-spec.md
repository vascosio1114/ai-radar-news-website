# AI Radar 博客寫作規範書

**版本：** 1.0
**日期：** 2026-05-11
**用途：** 規範每日 AI 新聞文章的全部創作標準

---

## 一、文章類型與定義

| 類型 | 比重 | 核心目的 | 情緒調性 |
|------|------|----------|----------|
| **快資訊** | 60% | 傳遞速度最快的新聞 | 中性客觀，結尾昇華 |
| **案例實戰** | 20% | 展示真實創業者/職場故事 | 激動人心，製造「我也可以」 |
| **深度分析** | 20% | 嚴謹論證觀點 | 令人不安，製造認知缺口 |

---

## 二、文字風格

### 2.1 總原則

- **販賣焦慮為手段，回應焦慮為目的**
- 每篇結尾必須有實際可行動的 CTA
- 不要只陳述事實，要陳述「別人沒告訴你的那一面」

### 2.2 句式長度

| 句式類型 | 平均字數 | 用途 |
|---------|----------|------|
| 短句 | 8-15 字 | 製造節奏感，強調重點 |
| 中句 | 20-35 字 | 主線敘述 |
| 長句 | 40-60 字 | 補充背景，偶爾使用 |

**每段不超過 3 句。** 段落超過 5 行立即拆分。

### 2.3 遣詞原則

**禁用詞（替換方案）：**
- 「重要的」→ 刪除或換更具體形容詞
- 「非常」→ 直接刪除或換精確詞
- 「我們相信」→ 刪除，直接陳述
- 「可以幫助你」→ 刪除，直接說「為你」
- 「據悉」→ 「根據 X 報告」或「消息顯示」

**情緒鉤子詞（每篇至少用 2 個）：**
- 警覺詞：隱藏、封鎖、掩蓋、秘而不宣、這一次
- 緊迫詞：立刻、馬上、馬上就到、倒計時、現在開始
- 獨家詞：你不知道的、內幕、華爾街不會告訴你的、沒人說的
- 對比詞：兩極、鴻溝、分野、這不是巧合

### 2.4 標題公式

```
[情緒詞] + [數字/年份] + [具體事實] + [問句或驚嘆]
```

**範例：**
- 快資訊：「獨家：OpenAI 封鎖了什麼？GPT-5.5 的安全迷霧」
- 案例：「裁員 40% 還能股價暴漲 20%：Jack Dorsey 的 AI 賭局」
- 深度：「華爾街正在讓 AI 逃離實驗室——而你連規則都看不懂」

## 三、數據使用規範

### 3.1 數字放大原則

| 原始數據 | 放大後呈現 | 效果 |
|---------|-----------|------|
| 4.5 倍 | 「4.5 倍——相當於你的公司被闖入 4 次」 | 具象化 |
| 64% | 「每 10 家公司裏，有 6 家還沒搞明白 AI 安全就已經在用了」 | 場景化 |
| 12 倍 | 「12 倍——這個增速比 2000 年互聯網爆發還快」 | 對比化 |

### 3.2 數據引用格式

每次引用數據必須同時呈現：
1. **數據本身**（精確數字）
2. **來源**（機構/媒體名稱）
3. **發布日期**（精確到年月）
4. **原文連結**（URL）

## 四、視覺元素規範

### 4.1 圖片使用時機

| 內容類型 | 是否用圖 | 圖片要求 |
|---------|---------|---------|
| 新聞事件（人物/公司） | ✅ | 人物頭像或公司 Logo，來自維基/官網 |
| 數據對比 | ✅ | 柱狀圖或折線圖，自製 |
| 裁員/衝突事件 | ✅ | 新聞現場圖，版權免費圖庫 |
| 模型 Benchmark 對比 | ✅ | 表格優先，圖表次之 |
| 深偽/安全漏洞 | ✅ | 模擬圖或示意圖 |
| 無合適圖時 | ✅ | 用色塊分割線或引用框代替 |

**圖片尺寸：** 寬度不超過 800px，高度自適應
**圖片版權：** 僅使用 Unsplash、Pexels（免費）或自製圖表

### 4.2 表格使用時機

| 內容 | 是否用表格 |
|-----|---------|
| 多公司/多模型橫向對比 | ✅ 強制 |
| 時間線事件羅列 | ✅ 強制 |
| 價格/功能對比 | ✅ 強制 |
| 單一數據說明 | ❌ 用一句話代替 |

### 4.3 圖表使用時機

| 內容 | 圖表類型 |
|-----|---------|
| AI 崗位增長趨勢 | 折線圖（2020-2026） |
| 安全事件率對比 | 柱狀圖（合規 vs 過度授權） |
| 模型 Benchmark 對比 | 水平柱狀圖 |
| 薪資兩極化 | 組合圖（柱狀+折線） |

## 五、文章結構模板

### 5.1 快資訊模板（600-800字）

```
[標題：情緒化、具體、含數字]

導讀（1-2句，50字以內）：
「[平台/機構]剛剛發佈瞭[事件]——這件事背後藏著你不知道的 [1個詞]。」
例：「OpenAI 剛剛發佈 GPT-5.5——華爾街卻在偷偷研究它會讓多少白領失業。」

正文結構：
第一段（100字）：[誰] 在 [何時] 做瞭 [何事]，要精確
第二段（200字）：為什麼這件事重要——引用數據
第三段（250字）：這件事對誰影響最大——具體群體
第四段（150字）：接下來會怎樣——未來預測
結尾（50字）：一句話昇華 + CTA

[ CTA區域 ]
```

### 5.2 案例實戰模板（800-1000字）

```
[標題：[數字]人/[金額]的故事 + 反差標的]

導讀（2句）：
「當 [機構] 宣佈 [事件]，華爾街的反應是 [行為]。但真正的故事藏在 [細節]。」

正文結構：
第一段（150字）：事件基本事實
第二段（300字）：創業者/當事人做了什麼，具體步驟
第三段（200字）：為什麼大多數人會失敗——對比
第四段（200字）：你現在可以複製的 3 個行動點
結語（100字）：昇華 + CTA

[ 行動清單框 ]
[ CTA區域 ]
```

### 5.3 深度分析模板（1000-1500字）

```
[標題：挑釁性陳述 + 問句]

導讀（2-3句）：
「大多數人以為 [普遍認知]。但證據顯示 [反向事實]。這關乎 [讀者切身利益]。」

正文結構：
第一段（200字）：設定框架——什麼正在發生
第二段（300字）：證據一——數據/研究支持
第三段（300字）：證據二——行業實例
第四段（300字）：證據三——歷史對比/類比
第五段（200字）：為什麼現在是轉折點
結語（150字）：你的選擇 + CTA

[ 大引用框（可放在任意段落之間）]
[ CTA區域 ]
```

## 七、CTA（行動呼籲）規範

### 7.1 CTA 位置

**每篇文章固定 2 個 CTA：**
1. 文章末尾（正文最後一段之後）
2. 固定懸浮按鈕（右下角，滑動始終可見）

### 7.2 CTA 文案替換規則

| 文章類型 | CTA 標題 | CTA 描述 |
|---------|---------|---------|
| 快資訊 | 「每日 AI 快報」 | 「每早收到當天最重要的 3 條 AI 新聞，領先別人一步」 |
| 案例實戰 | 「實戰案例內參」 | 「真實創業者怎麼用 AI 賺錢，每週精選 →」 |
| 深度分析 | 「每月深度報告」 | 「我如何看待 AI 巨變，每月一篇，僅發給訂閱者」 |

### 7.3 CTA 設計樣式

```
[大字體 CTA 標題]
一行描述 + 一個箭頭
[橙色實心按鈕：立即訂閱 →]
副文字：超過 12,000 人已訂閱 · 免費加入
```

## 八、圖片獲取策略

### 8.1 圖片來源優先級

1. **新聞事件圖**：維基百科、機構官網、新聞網站（標示來源）
2. **公司/人物圖**：官方新聞稿、LinkedIn、Twitter（標示來源）
3. **數據圖表**：用程式生成（Chart.js 或直接 HTML/CSS）
4. **情緒圖**：Unsplash / Pexels（搜索關鍵詞：anxiety, future, technology, isolation）

### 8.2 圖片尺寸要求

| 用途 | 尺寸 |
|------|------|
| 文章頂部大圖 | 1200×630px |
| 段落間插圖 | 800×450px |
| 數據圖表 | 800×400px |
| 人物頭像 | 200×200px 圓形 |
